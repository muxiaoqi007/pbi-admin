# Power BI 管理员运维工具（pbi-admin）实施计划

## 目标
一个自托管的 Web 运维工具，**同时适配国际版和世纪互联版** Power BI，以服务主体（应用身份）调用 Power BI 管理 REST API，实现：全租户工作区/报表/数据集浏览、工作区与报表的用户查看、报表与数据集的数据源查看、数据集的前端报表反查、刷新记录查看、触发刷新（全部刷新 / 选表刷新）。

## 技术选型（已确认）
- **Next.js 14（App Router，TypeScript）+ Ant Design 5**：前后端一体，API Route Handlers 在服务端持有密钥并代理 Power BI REST，浏览器不接触凭据。
- 数据获取：前端 SWR + 自建 `/api/*`；全租户快照在服务端内存缓存 5 分钟。
- 配置存本地 `data/config.json`（加入 .gitignore），也支持 `.env` 默认值。

## 双云适配设计（核心）
`lib/cloud.ts` 定义云环境，设置页可切换（高级设置允许覆盖 URL）：

| | 国际版 | 世纪互联 |
|---|---|---|
| Authority | `https://login.microsoftonline.com/{tenant}` | `https://login.chinacloudapi.cn/{tenant}` |
| API 基地址 | `https://api.powerbi.com/v1.0/myorg` | `https://api.powerbi.cn/v1.0/myorg` |
| Token Scope | `https://analysis.windows.net/.default` | `https://analysis.chinacloudapi.cn/powerbi/api/.default` |

认证：client_credentials 流程（原生 fetch，无需 MSAL 依赖），token 内存缓存、过期自动刷新。

## 功能 → API 映射
| 功能 | 端点（相对 API 基地址） |
|---|---|
| 全部工作区+用户+报表+数据集 | `GET /admin/workspaces?$expand=users,reports,datasets`（$top/$skip 分页，服务端聚合缓存） |
| 报表的用户 | `GET /admin/reports/{rid}/users` |
| 数据源 | `GET /admin/datasets/{did}/datasources`（报表→数据源 = 报表绑定的数据集再查其数据源） |
| 数据集关联的前端报表 | 快照中按 `report.datasetId` 反查（跨工作区） |
| 刷新记录 | `GET /admin/workspaces/{wid}/datasets/{did}/refreshes` |
| 数据集表清单 | `GET /groups/{wid}/datasets/{did}/tables` |
| 触发刷新 | `POST /groups/{wid}/datasets/{did}/refreshes`：经典全部刷新（notifyOption=NoNotification）或增强刷新（`objects:[{table}]` 选表，可配 retryCount/maxParallelism/commitMode）；容量不支持增强刷新时透传 API 错误 |
| 批量把服务主体加入工作区（解锁刷新权限） | `POST /admin/workspaces/{wid}/users` |
| 总览刷新状态 | `GET /admin/refreshables`（失败可优雅降级隐藏） |

## 页面结构
1. `/settings` 设置页：云环境、tenantId、clientId、clientSecret、测试连接
2. `/` 总览：工作区/报表/数据集/用户统计卡片 + 租户刷新状态表
3. `/workspaces` 工作区列表 → `/workspaces/[id]` 详情（成员角色表格 + 报表/数据集 Tab）
4. `/reports` 全租户报表：搜索筛选；行操作 = 查看用户、查看数据源、打开 Power BI 链接
5. `/datasets` 全租户数据集：行操作 = 数据源、关联报表、刷新记录（抽屉）、立即刷新（弹窗：全部/选表+高级参数）
6. `/tools` 运维工具：批量将服务主体加入（选中/全部）工作区

## 实施步骤
1. `create-next-app@14` 脚手架（TS、App Router、无 Tailwind），安装 antd / @ant-design/nextjs-registry / @ant-design/icons / swr
2. `lib/`：cloud.ts（双云端点）、config.ts（配置读写+脱敏）、auth.ts（token 获取缓存）、pbi.ts（REST 客户端+分页聚合）、types.ts
3. `app/api/*` 路由：config、test（测试连接）、workspaces、workspaces/[id]、reports/[rid]/users、datasets 相关、refresh（POST）、tools/sp-workspaces、refreshables
4. UI：布局（侧边菜单）+ 上述 6 个页面 + 公共组件（用户抽屉、数据源弹窗、刷新弹窗）
5. README：国际版/世纪互联各自的应用注册指引（Entra → 应用注册 → 密钥 → Power BI API Application 权限：Workspace.ReadWrite.All / Report.Read.All / Dataset.ReadWrite.All → 开启「允许服务主体使用 Power BI API」租户设置）+ 启动方式
6. `npm run build` + lint 验证；真实环境需你填入凭据后在设置页「测试连接」

## 已知边界（会在 README 说明）
- 触发刷新无 admin 直通端点，服务主体需先加入目标工作区（工具内置批量加入功能解决）。
- 选表刷新走增强刷新 API，个别容量/数据集类型可能不支持，报错会原样透传。
- 世纪互联若 authority 变更（login.chinacloudapi.cn → login.partner.microsoftonline.cn），高级设置可直接覆盖。
