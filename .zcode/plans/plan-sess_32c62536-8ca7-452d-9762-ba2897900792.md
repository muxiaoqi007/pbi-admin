# Power BI 运维平台产品化重构计划

## 市场调研结论

参考了 [DataTako](https://datatako.com/)（报表分享门户：白标、viewer 管理、RLS 自动应用、活动跟踪）、[EmbedFAST](https://maqsoftware.com/products/embedfast)（嵌入管理层：多租户、token 管理、角色权限）和治理类产品（[Atlan](https://atlan.com/power-bi-data-governance/)、[Dataedo](https://dataedo.com/blog/power-bi-data-governance-from-chaos-to-trusted-insights-practical-guide)：元数据目录、数据集文档、lineage）。

**定位**：双模式产品 — 管理员运维台 + 业务报表门户

## 产品信息架构

```
管理员模式（重组现有功能）
├── 总览        健康度一屏：失败巡检、关键统计、容量状态
├── 内容
│   ├── 工作区
│   ├── 报表
│   ├── 数据集
│   └── 数据源
├── 刷新运维    刷新监控、失败巡检、批量操作
├── 使用分析    报表活跃度排行、用户访问行为（新）
├── 门户管理    报表分组、门户配置（新）
└── 设置        多环境、认证

业务门户模式（新增，/portal）
└── 报表目录    卡片式、分组浏览、收藏、全局搜索、点击即预览
```

## 分期开发

### Phase 1: 产品化 UI 基础
1. 合并 feature/embedded-reports 分支
2. 导航分组重构（菜单分组标题：内容/运维/系统）
3. 全局搜索组件（Header 搜索框：跨工作区/报表/数据集，搜索结果跳转）
4. 面包屑导航

### Phase 2: 数据集文档化
1. SQLite 新表：dataset_notes（数据集级备注）、column_notes（字段级备注）
2. Schema 抽屉支持行内编辑备注（数据集描述、每个字段的业务含义）
3. 文档导出（CSV/Markdown）
4. 数据集列表显示"已文档化"标记

### Phase 3: 使用分析
1. 探测活动 API（/admin/activityevents，世纪互联可用性待验证）
2. 报表活跃度排行（打开次数、独立用户数）
3. 用户访问行为（谁最近看了什么）
4. 不可用时优雅降级

### Phase 4: 业务门户模式
1. /portal 路由：卡片式报表目录（不显示管理操作）
2. 报表分组管理（SQLite：portal_groups + portal_group_items）
3. 收藏功能（localStorage）
4. 门户内点击报表 → 全屏嵌入预览（复用 EmbedReportModal）
5. Header 模式切换（管理台 ↔ 门户）

## 技术要点
- 全部新数据存 SQLite（catalog-store.ts 扩展），按环境隔离
- 使用分析优先 DAX/管理 API 探测，不可用降级
- 门户模式复用现有 snapshot 数据，不增加 API 压力

## 验证
- 每期构建通过 + 真实租户验证
- 最终推送 feature 分支
